# 更新日志规范

## 记录范围

`CHANGELOG.md` 是面向玩家的版本记录。正式发布时必须使用用户提供的版本号，只写该版本自上一版本发布后实际包含、最终交付且玩家可感知的新增、修改、优化和修复。

可以写：新模式、新模块、新敌机、可见 UI 变化、玩家能感知的平衡调整、真实修复。

不要写：内部测试、调试日志、重构、变量改名、临时方案、未开放代码、实验性实现、发布包重建或未经证实的推测。

## 事实来源与版本边界

优先检查：

1. 上一个版本提交之后的 `git diff`。
2. 当前代码和真实玩家入口。
3. 本次任务记录与已验证测试。
4. 用户提供的目标版本号、Git 提交标题和发布日期。

旧版本已经记录过的功能不得重复搬到新版本；不属于用户提供版本号对应范围的内容也不得写入。若无法确认一项是否属于本次版本，默认不写并询问用户。

## 强制确认流程

正式发布时，修改 `CHANGELOG.md` 前必须先把按用户提供版本号准备写入的全部标题和条目一次性列给用户，等待明确确认。确认前只能修改文档规则、功能文档或问题记录，不能偷偷写入 CHANGELOG；确认后才可继续提交、推送 GitHub 并触发 Pages 工作流。

确认后的每条内容都必须能够回溯到具体代码路径或 Git 改动；不要夸大范围，也不要把“实现但未开放”写成已开放功能。

## 推荐格式

```markdown
## vX.Y.Z

发布日期：YYYY-MM-DD

### 新增

- 玩家可以实际体验到的新增内容。

### 优化

- 玩家可感知的体验变化。

### 修复

- 已验证并完成的玩家问题修复。
```
