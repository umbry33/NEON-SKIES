# 修复点击与触控

处理本项目任何点击、触控、按钮、菜单、UI 或 Canvas 交互问题时，先遵守根目录 `AGENTS.md` 的“点击与触控交互强制规范”；本 Skill 提供执行顺序和验收方法。只修改规则要求的最小范围，不改动当前游戏代码以外的无关系统。

## 执行流程

1. 读取 `AGENTS.md`、`docs/AI_HANDOFF.md`、`docs/DEVELOPMENT_RULES.md`，再读取与入口、UI、输入或当前模式有关的专题文档。
2. 记录复现步骤、目标元素、电脑端和手机端的现象；先确认原有视觉样式、布局和点击手感，作为修复基线。
3. 先定位真实事件链，按顺序检查：
   - 透明 DOM、Canvas 或其他层覆盖，以及 `z-index`、`pointer-events`；
   - 重复事件监听和 `touch`、`mouse`、`pointer` 事件互相竞争；
   - `preventDefault()`、`stopPropagation()`、全局捕获监听是否错误吞掉事件；
   - 拖拽状态、移动阈值、Canvas 命中检测和点击过程中重建 DOM；
   - 移动端浏览器默认滚动、缩放或手势行为。
4. 选择最小根因修复：普通按钮保持“按下 → 保持 → 松开 → 确认触发”的 click/tap 语义。不得把主要操作改成 `pointerdown`、`mousedown` 或 `touchstart` 立即执行。
5. 如果且仅如果证据确认命中区域过小，才使用不改变视觉和布局的透明 hit area/hitbox；不得放大按钮或修改字体、间距、位置、页面比例来绕过问题。
6. 若元素同时支持点击和拖拽，使用合理移动阈值区分两者；轻微抖动仍应在松开时触发点击。
7. 防止重复触发：避免 `touchend + click` 或 `pointerup + click` 竞争；能使用统一 Pointer Events 时不要维护互相竞争的多套事件系统。

## 验收要求

修复必须同时验证：

- Windows：鼠标点击、鼠标松开、拖拽、普通 UI 点击。
- 手机：单指 tap、按下/移动/松开、页面滚动、游戏触控。
- 一次操作只触发一次，不误触，不影响其他按钮和拖拽。
- 原有视觉设计、按钮尺寸、布局和松开触发手感保持不变。
- 浏览器控制台无新增错误；必要时按项目测试清单运行本地页面和逻辑测试。

## 不确定时停止

如果无法可靠确定根因，不要连续试用不同事件模型，不要不断扩大按钮，也不要重写输入系统。停止修改并向用户报告：当前现象、已定位的事件链、最可能原因、建议修改位置和仍需确认的内容。

## 交付说明

完成后说明根因证据、实际修改文件、电脑/手机验证范围，以及是否保留了原有 UI 外观和 click/tap 语义。若只完成诊断，明确标注“未修改代码”。
